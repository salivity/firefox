Firefox Benchmarking: Cold vs. Warm Startup Explained

Benchmarking the Firefox web browser requires measuring how quickly the application launches under different system conditions, primarily categorized as cold and warm startups. This article explains the fundamental differences between these two testing scenarios, detailing how system memory and storage caching affect browser launch times, how testers simulate these environments, and why Mozilla developers measure both metrics to optimize overall browser performance.

What is a Cold Startup?

A cold startup occurs when you launch Firefox for the first time after turning on or rebooting your computer. In this state, none of the browser's executable files, libraries, or user profile data are stored in the system's Random Access Memory (RAM).

When a cold startup test is initiated:

  • The operating system must locate the required Firefox files on the physical storage drive (SSD or HDD).
  • The data is read from the storage drive and loaded into the RAM.
  • The CPU processes the data to initialize the browser and render the user interface.

Because reading data from a storage drive is significantly slower than reading from RAM, a cold startup is the slowest way Firefox can launch. In benchmarking, it represents the worst-case scenario for startup performance and is heavily bottlenecked by the speed of the computer's storage drive (Disk I/O).

What is a Warm Startup?

A warm startup occurs when you launch Firefox after it has already been opened and closed at least once during the current operating system session.

When you close Firefox, the operating system does not immediately erase the browser's files from the RAM. Instead, it keeps them in a standby memory cache. When a warm startup test is initiated:

  • The operating system recognizes that Firefox's core files and libraries are already present in the RAM.
  • It bypasses the physical storage drive entirely (or almost entirely).
  • The CPU immediately begins executing the code and rendering the browser window.

A warm startup is drastically faster than a cold startup. In benchmarking, this metric removes the storage drive bottleneck, allowing developers to measure how quickly the CPU and Firefox's internal code can initialize the application.

Key Differences in Benchmarking Methodology

When benchmarking Firefox, testers must use strict methodologies to ensure they are accurately measuring either a cold or warm state without cross-contamination.

  • Hardware Bottlenecks: Cold startup benchmarks primarily test Disk I/O (how much data Firefox requests from the hard drive and how fast the drive provides it). Warm startup benchmarks test CPU processing and RAM efficiency.
  • Test Preparation: To run a valid cold startup benchmark, the tester must either reboot the computer before every single test run or use specialized command-line tools to manually flush the operating system's file cache. To run a warm startup benchmark, the tester launches Firefox, closes it to populate the RAM cache, and then measures the time it takes to launch it a second time.
  • User Experience Representation: Cold startups measure the experience of a user booting up their PC at the start of the day and opening Firefox. Warm startups measure the experience of a user who accidentally closes their browser and immediately reopens it.

Why Both Metrics Matter for Firefox

Mozilla engineers use data from both benchmark types to make different kinds of improvements to Firefox.

If cold startup times are too slow, engineers focus on reducing the total size of the files Firefox needs to load at launch, rearranging how data is read from the disk, or leveraging operating system pre-fetching features.

If warm startup times are too slow, engineers know the hard drive is not to blame. Instead, they focus on optimizing Firefox's internal initialization code, delaying the loading of non-essential components (like background updates or certain extension processes), and speeding up the rendering of the initial browser window.
